## 5. 기존 방법론의 실제 결함과 수정 후보

1. **기계 상태를 의미로 오인:** CORE/ACCEPTED/EXECUTABLE, density, boxClose는 코드 정의다. 책의 중요선·진짜 매물대·안전 진입과 동일시하면 잘못된 확신을 만든다.
2. **자료 부족을 높은 확률로 덮음:** RR=null, 안 보이는 공급·동시간량, 미완성봉을 알고도 빈칸을 채우면 실제 판단이 나빠진다. 누락은 명시하고 그 항목에 의존하는 행동만 보류한다. 모든 누락을 전체 후보 자동 거절로 바꾸지 않는다.
3. **확인을 기다린 뒤 진입선은 더 깊게 둠:** Work C의 강한 추세 누락을 보존한다. 확인 진입도 평가 가능한 대안으로 두되, 추격이 유리하다고 뒤집지 않는다. 판단 대상은 대안별 현재 위험/남은 공간/비체결 비용이다.
4. **ADD를 배수 위험만 보고 사실상 금지:** Work C ADD0은 능력 증명이 아니다. 새 지지에서 소량을 추가하는 대안까지 전체 위험으로 비교해야 한다. 근거 없는 일률적 추가도 금지한다.
5. **후속 매도 연결 약함:** 후보를 잘 거절하는 능력만으로 긴 추세 참여·효율적인 부분/전량 청산은 입증되지 않는다. 스캐너의 일일 상태 갱신은 실제 보유 장부를 대체하지 않는다.
6. **소급 가능한 구조 날짜:** 후속 봉을 필요로 하는 구조의 표시 날짜와 최초 이용 가능 시각은 다르다. 이를 바꾸지 않고 역사 평가에 사용하면 실제보다 좋아 보일 수 있다. 이번에는 코드 수정 없이 사용 경계를 기록한다.

연구의 기여는 위 오류를 막는 자료 해석과 행동 절차의 후보를 만든 것이다. 개선된 매매 성과·독립능력·스캐너 자체 품질의 향상을 입증한 것은 아니다. [MASTER 후보](MASTER_CANDIDATES/INTRO_PRACTICAL_MASTER_20261103.md)는 기존MASTER를 대체하지 않으며 실제 주문 허가도 아니다.

## 6. 보존 검증

기존 연구 validator PASS, 무결성 단위검사29건 PASS, 기존 strict-HOLD 주문의도 단위검사8건 PASS. 기록88→89의 로컬 검증 스냅샷에서 append-only 검사 PASS. 이는 파일 보존·연구 경계 검사이며 신규 차트시험/매매 시뮬레이션이 아니다. MASTER·LESSONS·CASES·Work C 최종 보고서의 기준 HEAD 원문 bytes 일치 확인. GitHub에는 출처 checkpoint와 연결/후보 checkpoint를 나누어 저장하고 각 저장 내용을 다시 열어 확인한다.
